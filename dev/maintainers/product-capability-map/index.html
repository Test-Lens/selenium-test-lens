    Product capability map for release 0.5.0¶

    This inventory is the maintenance source behind the documentation landing page. It records behavior shipped by the immutable v0.5.0 release, separates supported consumer entry points from published implementation dependencies, and does not treat every technically public Java class as stable API.

    Audit boundary¶

    • Consumer target: io.github.test-lens:*:0.5.0 and the fully qualified Studio goal io.github.test-lens:test-lens-test-engineering-maven-plugin:0.5.0:studio.
    • Release implementation: annotated tag v0.5.0 (ad22a8580f7c820e9d7f3e7a87fbbaf00ea0b9be).
    • Repairable documentation source: an explicitly reviewed post-tag documentation commit prepared on main and selectively applied to release/0.5.0; redeploy-release verifies the 0.5.0 source version and changes documentation only, without moving the tag or changing released runtime/API semantics.
    • Published stable artifacts: parent POM, selenium-test-lens-core, selenium-test-lens-overlay, selenium-test-lens, selenium-test-lens-junit5, selenium-test-lens-testng, selenium-test-lens-allure, and selenium-test-lens-react.
    • Published tooling dependencies: selenium-test-lens-application-model, selenium-test-lens-application-mapper, selenium-test-lens-application-tooling, selenium-test-lens-selector-engine, selenium-test-lens-selector-live, selenium-test-lens-selector-tooling, selenium-test-lens-test-engineering-studio, and test-lens-test-engineering-maven-plugin.
    • Not published for consumers: examples, browser tests, Selector Lab, compatibility engine/tooling, and migration tooling retain maven.deploy.skip; they are test, demo, or internal maintenance surfaces.
    • API compatibility boundary: the generated 0.5.0 catalog contains 728 public types and 5,235 callables. The compatibility promise covers the explicitly classified 120 USER_API and 143 ADVANCED_API types, not all public classes in tooling JARs.

    The exact public type and callable inventory remains generated in the public API catalog. This map groups that surface by user problem and records representative evidence; it is not a replacement for signature documentation.

    Integration and daily browser work¶

    Capability User problem and released behavior Public entry point / artifact Activation, requirements, and limits Detailed docs Confirming example, test, and availability source
    Attach to an existing driver Adds one Lens lifecycle around a consumer-owned WebDriver; manual finalization produces evidence but never closes the driver. TestLens.attach(...), startSession, finishPassed/Failed/Skipped; selenium-test-lens Explicit setup and finalization. Existing factory, Page Objects, runner, and quit() ownership can remain. Getting started, TestLens lifecycle SeleniumUsageExampleTest, TestLensTest; present in v0.1.0 and v0.4.0.
    Observe ordinary Selenium A returned WebDriver facade and explicitly wrapped elements preserve supported native Selenium semantics while adding correlation, duration, source, redaction, and visual diagnostics. Commands delegate once. observeDriver(), observe(WebElement, label); selenium-test-lens Opt-in in 0.4.0. Old references are not instrumented. Does not add Smart Click, waits, recovery, or JS fallback. Existing calls NativeSeleniumObservationTest, NativeSeleniumObservationIT, NativeSeleniumObservationExampleTest; introduced in v0.4.0.
    Semantic and Selenium locators Builds lazy UiLocator values from By or test id, text, label, placeholder, alt text, and role/name intent. locator, getByTestId/Text/Label/Placeholder/AltText/Role; selenium-test-lens Lens-native API. Role/name uses browser/WebDriver accessibility data and does not implement the ARIA algorithm itself. Locators SemanticLocatorTest, UiLocatorSelectorsTest, PlaywrightStyleLocatorsExampleTest; factories are present in v0.4.0, with strengthened accessibility behavior documented for 0.2.0+.
    Scoped queries and collections Searches descendants without escaping the selected parent; filters parents by descendants/text/attributes and provides ordered positional selection, snapshots, counts, and count waits. UiLocator.locator/filterHas/filterBy*/nth/first/last/resolveAll/count/waitUntilCount*; selenium-test-lens Lazy immutable pipeline; current frame/window only; no automatic shadow-root traversal. Locators, collections CompositeLocatorTest, UiLocatorCollectionTest; public in v0.4.0. First-version badges are omitted because individual pipeline operations evolved across early releases.
    Element state reads Reads text content, accessible name, visibility, enabled state, value, DOM attributes/properties, checked state, and selected option data. UiLocator.textContent/accessibleName/isVisible/isEnabled/value/attribute/property/isChecked/selected*; selenium-test-lens Reads the current resolved state; does not imply polling unless a wait/assertion method is used. Element information, select controls UiLocatorTest, UiLocatorSelectTest, UiLocatorFormActionsTest; public in v0.4.0.
    Actions and form controls Clicks, fills, clears, presses keys, hovers, double/right clicks, checks/unchecks, uploads, focuses, scrolls, and selects native options with operation diagnostics. UiLocator action methods; selenium-test-lens Method-specific Selenium/Actions/JS contracts. Upload requires valid local paths; select helpers require native <select>. Actions, select controls UiLocatorTest, UiLocatorFormActionsTest, UiLocatorSelectTest; public in v0.4.0.
    Bounded Smart Click Uses one deadline across native click and controlled fallbacks, with target-owned hit testing for physical fallbacks and configurable final JS dispatch. UiLocator.click(), UiLocatorOptions.javascriptClickFallback; selenium-test-lens Lens-native only. Hidden/disabled targets fail; no ancestor substitution, DOM mutation, blind second click, or universal success guarantee. Click contract SmartClickFallbackCascadeTest, HighlightClickContractTest, real-browser contracts; behavior strengthened in 0.4.0, earlier click capability predates it.
    Browser context Wraps frame, parent/default content, window/tab, new-window, and alert/confirm/prompt work while preserving explicit context ownership. TestLens.switchToFrame/...Window, alert(); selenium-test-lens Uses current Selenium session; no automatic context discovery across arbitrary boundaries. Browser context TestLensBrowserContextTest, TestLensAlertTest, browser contracts; public in v0.4.0.
    Overlay/popup handling Diagnoses known blockers and executes configured actions for declared overlay policies. OverlayPolicy, OverlayHandler, Guards; selenium-test-lens Requires explicit selectors/actions; does not infer every application popup or guarantee recovery. Overlay policies OverlayPolicyTest, OverlayHandlerTest, OverlayPolicyExampleTest; public advanced API in v0.4.0.

    Waiting, assertions, and recovery¶

    Capability User problem and released behavior Public entry point / artifact Activation, requirements, and limits Detailed docs Confirming example, test, and availability source
    Element and collection waits Re-resolves and polls visible, hidden, Selenium-clickable, text, and collection-count conditions using locator timeout/poll settings. UiLocator.waitUntil*; selenium-test-lens Explicit call. Clickability is not proof against the next interception. Polling is not recovery retry. Waiting UiLocatorTest, UiLocatorCollectionTest, LocatorOptionsPropagationTest; public in v0.4.0.
    Page/application waits Polls document ready states, an installed XHR/fetch-idle tracker, DOM stability, roots, and combined React/network stages. TestLens.waitForPageReady/waitForInteractiveOrComplete/waitForNetworkIdle, PageWaits, JsOverlayDebug; selenium-test-lens Each method has a narrower observation contract. XHR/fetch idle misses earlier and non-XHR/fetch resources. SPA helpers use observable DOM state. Page waits PageWaitsTest, PageWaitFacadeTest; public in v0.4.0.
    Polling assertions Polls element, collection, and current-page conditions and returns structured results or throws structured assertion failures. UiExpect, UiPageExpect, UiAssertionOptions/Result/Error; selenium-test-lens State reads only; does not click or count polls as recovery. URL matching is raw/case-sensitive; title matching uses configured text semantics. Assertions UiExpectTest, UiExpectStateAssertionsTest, UiPageExpectTest, RetryableAssertionsExampleTest; public in v0.4.0.
    Recovery diagnostics and outcome policy Records failed physical attempts that lead to another attempt, summarizes recovered instability, and can report, warn, or reject an otherwise passed result after evidence. RetrySummary, RetryOutcomePolicy, UiLocatorOptions; core/main artifacts Configured recovery only. Distinct from condition polling, runner retry, and CI job retry; does not promise elimination of flakiness. Flakiness UiLocatorRecoveryRetryTest, RetrySummaryTest, runner retry policy tests; public in v0.4.0, with policies expanded before/through 0.4.0.

    Screenshots Captures viewport evidence and bounded opt-in full-page scroll-and-stitch output through WebDriver. captureScreenshot, ScreenshotCaptureOptions/Result; selenium-test-lens VIEWPORT default.     Failure bundles On final failure, independently collects configured screenshots, trace/report, failure/context, runtime/config allowlists, network summary, manifest, directory, and ZIP. FailureBundleOptions, normal failed finalization; selenium-test-lens Best effort; collector failures do not replace the original failure. Page source/console are optional and bounded. CI owns retention. Failure bundles FailureBundleCaptureTest, evidence browser tests; added in 0.2.0 and present in v0.4.0.
    Existing video attachment Adds metadata/reference for a recording supplied by the caller. VideoEvidence, options/result; selenium-test-lens Lens does not record or redact video. Video evidence VideoEvidenceTest, VideoEvidenceExampleTest; public in v0.4.0.
    Explicit HTTP report upload Packages completed output and synchronously sends it to a configured endpoint with controlled auth, size, proxy, checksum, idempotency, and retry options. ReportUploader, ReportUploadOptions; selenium-test-lens Explicit finish → upload → quit; never automatic and never owns WebDriver. Receiver and CI retention are external. Report upload ReportUploaderTest; public in v0.4.0. First-version badge omitted.
    Allure attachment Attaches selected finalized Lens evidence to the active Allure test/step. AllureTestLens.attach(...); selenium-test-lens-allure Optional artifact and active Allure lifecycle. Does not recapture evidence or change Allure status. Allure AllureTestLensTest, AllureRunnerIntegrationTest; introduced in 0.3.0.

    Network, data protection, state, and optional modules¶

    Capability User problem and released behavior Public entry point / artifact Activation, requirements, and limits Detailed docs Confirming example, test, and availability source
    Passive BiDi network diagnostics Correlates requests, completed responses, redirects, and fetch errors; provides snapshots, waits, assertions, HUD filtering, evidence, and summaries. NetworkDiagnostics, NetworkDiagnosticsOptions, network models; selenium-test-lens Selenium Java 4.39.0+, compatible browser/driver/transport, BiDi-enabled session, explicit start. No interception, mocking, bodies, performance-log, or CDP fallback. Network network unit tests and NetworkBiDiBrowserIT; manual network events existed earlier, typed BiDi surface present in v0.4.0.
    Caller-supplied API preview Displays a modal around an API operation whose method/URL/payload/result preview is provided by the caller. apiCallWithModal(...); selenium-test-lens Specialized visual helper. Does not observe browser traffic or perform interception. Visual helpers API overlay tests; public in v0.4.0.
    Diagnostic text redaction Creates redacted diagnostic copies for recognized credentials, configured keys/secrets, URLs, exceptions, network/API text, reports, and bundle text. RedactionPolicy; selenium-test-lens-core and main options Enabled by default; configurable; explicit disable can expose secrets. Does not discover arbitrary personal data or transform replayable auth files/pixels/video. Text redaction RedactionPolicyTest and boundary tests; central failure-bundle/redaction behavior added in 0.2.0.
    Screenshot visual redaction Adds browser-side SOLID/BLUR masks to configured regions and password inputs before screenshot publication. VisualRedactionOptions; selenium-test-lens Password SOLID defaults and STRICT fail-closed publication. Blur is not guaranteed anonymization; only Test Lens screenshot captures are covered. Visual redaction VisualRedactionCaptureTest, options tests, browser evidence contracts; introduced in 0.3.0.
    Managed Auth State Restores cookies/storage, validates through the application, performs at most one justified login, and atomically keeps/replaces state. Low-level capture/restore remains available. lens.authState().ensure(...), AuthStateManager; selenium-test-lens Same-origin controlled setup with locking and tri-state validation. State files may contain live credentials; no automatic cross-origin SSO or logout. Auth state managed/low-level auth unit tests and ManagedAuthStateIT; managed lifecycle introduced in 0.3.0.
    Managed test state/resources Isolates typed scenario state per physical invocation, shares suite state intentionally, and cleans resources exactly once in LIFO order. scenarioState, suiteState, resources; selenium-test-lens In-memory only; no disk/cross-JVM store. Runner adapters bind physical invocation boundaries. Managed state ManagedTestStateTest, JUnit/TestNG state tests; introduced in 0.3.0.
    React/SPA helpers Re-resolves across rerenders, checks observable busy/loading conventions, waits for roots/DOM stability, and handles known React Select markup. ReactSupport, ReactSafeExecutor, actionability types; selenium-test-lens-react Optional published module. No component-tree inspection, universal library support, or automatic frame/window/shadow traversal. React/SPA React module tests and examples; published from 0.1.0 through 0.4.0, with individual behavior evolving.
    Runner adapters Maps physical invocation outcomes to Lens lifecycle and cleans up only adapter-owned drivers. TestLensExtension; TestLensTestNgListener/factory/context; optional adapter artifacts Explicit runner configuration. JUnit/TestNG retries are new sessions; TestNG PER_CLASS requires sequential class methods. Framework integration, JUnit, TestNG extension/listener tests and browser ITs; adapters published from 0.2.0, TestNG PER_CLASS added in 0.4.0.
    Named steps and business assertions Adds domain-level step and assertion results to the same trace without replacing runner assertions/lifecycle. step(...), UiStep*, BusinessAssertions; selenium-test-lens Optional composition API; failures retain documented result/throwing behavior. Steps/business assertions step/business unit tests and examples; public in v0.4.0. First-version badge omitted.
    Execution/observability modes Selects headed/headless execution separately from DEFAULT/FAST presentation and passed-session trace retention. BrowserExecutionConfig, ObservabilityMode, TestLensOptions; selenium-test-lens 0.4.0. FAST changes presentation defaults, not Selenium/action/assertion/retry semantics or failed-session evidence. Configuration execution/mode unit tests and HeadlessExecutionConfigIT; introduced in 0.4.0.

    Selector Intelligence¶

    Capability Released 0.5.0 behavior Boundary and evidence
    Candidate generation and ranking Existing CandidateGenerator and CandidateRanker produce and order deterministic candidates. Mapper and repair reuse this engine rather than implementing locator heuristics. Published selector-engine dependency; tooling API unless explicitly classified otherwise.
    Live validation and target identity LiveCandidateAnalysisService resolves candidates in the explicit browser scope, records match count, uniqueness and executability, and requires same-target comparison before recommendation. Published selector-live dependency; analysis objects retaining WebElement remain internal/tooling.
    Stability policies Generated-looking IDs, hashes, counters, UUIDs, and framework tokens are evidence rather than final verdicts. Exact or structural project policy may declare a candidate stable or unstable without bypassing uniqueness and target checks. Selector Intelligence; engine and policy contract tests.
    Selector Audit and Find Similar Java declaration discovery, evidence-based audit, bounded history, and deterministic similarity relations support review and impact analysis. Similarity never means same element. Published selector-tooling implementation dependency; JavaParser-backed classes are not stable USER API.
    Selector Lab Read-only inspection UI over supplied selector evidence. Unpublished demo module with maven.deploy.skip; not a 0.5.0 consumer entry point.

    Application and existing-project intelligence¶

    Capability Released 0.5.0 behavior Boundary and evidence
    Application Model Selenium-free, versioned and deterministic pages, states, meaningful elements, transitions, provenance, completeness, limitations, and redacted selector projections. Published tooling format with schemaVersion; the whole Java model tree is not a stable interchange API promise.
    Application Mapper Bounded current-page and guided observation plus conservative opt-in safe exploration, backed by live Selector Intelligence. ApplicationMapper advanced facade; caller owns authentication, navigation, and browser context.
    Existing project index Conservatively indexes Java Page Objects/components, locator declarations, methods, inheritance, JUnit/TestNG tests, and source fingerprints. ExistingProjectIndexer; published tooling implementation, not a general Java compiler API.
    Correlation and usage graph Correlates application elements with source declarations using selector, page/context, and live evidence; builds bounded test to method to field to selector to application-element impact. PageObjectCorrelator and UsageGraph; ambiguous or probable evidence never authorizes repair apply.

    Test Engineering Studio and reviewed repair¶

    Capability Released 0.5.0 behavior Boundary and evidence
    Turnkey Studio The Maven goal discovers an existing project, opens a persistent .test-lens/ workspace, and serves a token-protected loopback UI for scan, map, correlate, plan, proposal, run, diagnosis, and repair review. test-lens-test-engineering-maven-plugin:0.5.0:studio and the small TestEngineeringStudio launcher facade.
    Browser and agent providers Local Chrome/Firefox use Selenium Manager; provider-neutral SPIs support trusted project browser factories and external agents with preflight and explicit ownership. BrowserSessionProvider and AgentExecutorProvider; no provider SDK is added to the ordinary runtime.
    Bounded external-agent workflow Architect, implementer, verifier, stabilizer, and reviewer exchange versioned structured artifacts over bounded context. Generated tests are Page-Object-only by default and checked for raw selectors, direct WebDriver, sleeps, JavaScript, retries, and path violations. External runner has bounded IO, timeout, environment allowlist, and no silent scripted fallback.
    Targeted subprocess execution JUnit class loading, static initialization, instance/setup/test execution, Lens finalization, and cleanup run in one child JVM under an absolute deadline. Timeout, System.exit, halt/crash, and interruption-resistant test code cannot kill or outlive the Studio/workflow host; diagnostics and protocol are bounded.
    Evidence-based repair Failure classification, exact/strong source correlation, live candidate validation, same-target, uniqueness, stability, and usage impact produce a PROPOSE_ONLY RepairProposal. AI never invents the replacement; proposal creation does not mutate source.
    Trusted repair and resume Only explicit human approval invokes the trusted host, which rechecks roots, symlinks, source/declaration fingerprints, old selector, and double-apply state. Workflow snapshots restore review state without silently rerunning agents, tests, or repairs. Studio repair and restart clean-room/browser certifications.

    Documentation tools versus runtime integrations¶

    Tool What it actually does Boundary and evidence
    HUD Studio Configures and previews the production HUD renderer, then generates matching Java configuration. Source-navigation behavior is safely simulated in the public demo. Documentation-only tool in docs/demo/hud-studio; validated by HUD Studio scripts and HudStudioDocumentationLayoutIT. It is not a separate runtime renderer or IDE probe.
    AI Integration Builder Generates one release-bound instruction for an external coding agent from selected integration choices. Documentation JavaScript, not an embedded model or guaranteed installer. Target version comes from extra.ai_integration.target_release; checked by check-ai-integration-builder.ps1.
    Test Engineering Studio Executes the reviewed local tooling workflow through the Maven goal and loopback host. Opt-in published tooling; normal selenium-test-lens runtime does not start it or acquire its dependencies.

    Version evidence policy¶

    The landing page uses 0.5.0 as the current stable release. A capability belongs here only when the immutable release tag, staged artifact set, focused tests, and clean-room certification support it. Publication of an implementation dependency does not promote all of its public classes into the compatibility promise. When a first version is stated in this map, it is supported by a release tag, archived documentation/release notes, and tests or examples from that line; @since alone is not the evidence.

    When maintaining this map:

    1. verify the symbol and behavior against the target tag or published artifact;
    2. confirm publication role and type-level API classification independently;
    3. cite a contract test/example and the focused guide;
    4. separate a long-standing capability from a later improvement;
    5. keep demos, test fixtures, parser internals, workflow storage, HTTP internals, process models, and trusted mutation implementations out of the advertised stable API.
